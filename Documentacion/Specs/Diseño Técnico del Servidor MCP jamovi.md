Especificación de Diseño Técnico: Servidor MCP jamoviMódulo: Núcleo de Orquestación, Puente R y Motor de Traducción GUIEstado: Design-First / Borrador TécnicoReferencia: Complementa SPEC-002 y SPEC-003 del Informe Técnico.1. Arquitectura del SistemaEl sistema opera como un microservicio encapsulado en Docker, exponiendo una interfaz MCP sobre transporte SSE (Server-Sent Events) para clientes en la nube o stdio para uso local.Componentes Principales:MCP Server Wrapper (Python/FastAPI): Gestiona el ciclo de vida del protocolo, la validación de esquemas Pydantic y el enrutamiento de llamadas.R Session Manager (CA-MCP): Mantiene hilos persistentes de rpy2. Asocia un session_id a un objeto data.frame en la memoria de R.jmv Engine Bridge: Traduce los diccionarios JSON de Python en llamadas sintácticas exactas a la librería jmv de R.GUI Translation Service: Analizador estático que cruza los parámetros de la herramienta con los archivos .a.yaml y .u.yaml de jamovi para generar instrucciones en lenguaje natural.2. Flujo de Datos (Sequence Diagram)Usuario/Agente: Envía una instrucción (ej. "Haz un t-test de la variable A por el grupo B").MCP Server: Valida argumentos. Verifica si el dataset_path existe en el volumen /data.R Session Manager: - Si no existe sesión, carga el archivo (.omv, .csv) usando jmvReadWrite.Mantiene el objeto en el entorno global de R.jmv Bridge: Ejecuta jmv::ttestIS(data = df, vars = 'A', group = 'B').Result Parser: - Intercepta el objeto R6.Extrae tablas mediante $asDF.Serializa matrices a Markdown/JSON.GUI Translator: Busca en ttestis.a.yaml y ttestis.u.yaml. Detecta que group corresponde a "Grouping Variable".Salida: Devuelve al agente el resultado estadístico + instrucciones de réplica en la GUI.3. Especificación de Herramientas (Tool Definitions)tool_run_analysisUnifica las llamadas a cualquier análisis de la suite jmv.Argumentos:analysis_name (string): Nombre interno de jamovi (ej. ttestIS, descriptives, anovaOneway).options (object): Diccionario de parámetros que coincidan con el .a.yaml.session_id (string): Identificador para persistencia de datos.tool_get_gui_guidePermite consultar la guía de réplica de un análisis previo sin volver a ejecutarlo.Argumentos:analysis_name (string).applied_options (object).4. Estrategia de Manejo de Errores (Error Mapping)Se implementará un interceptor de excepciones de R para mapear errores crípticos a mensajes amigables:Error en RMensaje Traducido (JSON-RPC Error)Acción Sugerida al Agentegrouping variable must have exactly 2 levels"La variable de agrupación tiene N niveles. Se requiere una Prueba T o ANOVA."Cambiar a jmv_anovaOneway.singular matrix"Colinealidad extrema detectada en el modelo."Eliminar variables redundantes.Memory limit reached"El conjunto de datos excede los 10MB permitidos."Submuestrear el dataset.5. Diseño del Motor de Traducción (GUI Translator Logic)El motor utilizará un mapeo estático de etiquetas basado en las definiciones de jamovi:Input: tool: jmv_descriptives, params: { vars: ['edad'], splitBy: ['genero'] }Logic: 1. Buscar descriptives.u.yaml.2. Identificar que el control para vars es un VariablesListBox dentro de un TargetLayoutBox con etiqueta "Variables".3. Identificar que splitBy tiene la etiqueta "Split by".Output: "1. Abre jamovi. 2. Ve a Analyses -> Exploration -> Descriptives. 3. Arrastra 'edad' a 'Variables'. 4. Arrastra 'genero' a 'Split by'."6. Seguridad y AislamientoHeadless Execution: No se intentará abrir ventanas de jamovi. Todo ocurre en el motor binario de R.Data Privacy: Los datasets en /data son de solo lectura. Los resultados en memoria se purgan tras 30 minutos de inactividad (REQ-2.4).
